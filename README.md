# 어르신 돌봄 대시보드 (Elder Care Dashboard)

## 📋 1. 앱 소개

*   **앱 이름**: 어르신 돌봄 대시보드 (Elder Care Dashboard)
*   **핵심 목표**: 혼자 계신 어르신의 건강과 안전을 통합적으로 관리하고, 위험 상황을 감지하여 보호자에게 알리는 것을 목표로 하는 웹 기반 모니터링 플랫폼입니다.

---

## 🚀 2. 시작하기 (Getting Started)

이 섹션은 소스 코드를 통해 프로젝트를 로컬 컴퓨터에 직접 설정하고 실행하는 방법을 안내합니다.

### ✅ 사전 요구 사항 (Prerequisites)

프로젝트를 실행하기 위해 아래 프로그램들이 설치되어 있어야 합니다.
*   [Python](https://www.python.org/downloads/) (3.10 이상 권장)
*   [Node.js](https://nodejs.org/ko/) (LTS 버전 권장)

### ⚙️ 설치 및 설정 (Installation & Setup)

Git 저장소를 복제한 후, 백엔드와 프론트엔드를 각각 설정해야 합니다.

**1. 백엔드 설정 (Backend)**

```bash
# 1. 백엔드 폴더로 이동합니다.
cd backend

# 2. 파이썬 가상 환경을 생성합니다.
python -m venv venv

# 3. 가상 환경을 활성화합니다.
# Windows:
venv\Scripts\activate
# macOS / Linux:
# source venv/bin/activate

# 4. 필요한 라이브러리를 설치합니다.
pip install -r requirements.txt
```

**2. 프론트엔드 설정 (Frontend)**

```bash
# 1. 프론트엔드 폴더로 이동합니다.
cd frontend

# 2. 필요한 라이브러리를 설치합니다. (시간이 다소 걸릴 수 있습니다.)
npm install
```

### ▶️ 실행하기 (Running the Application)

이 프로젝트는 백엔드 서버가 프론트엔드의 빌드 파일을 직접 제공하는 방식으로 작동합니다. 따라서 실행 전 프론트엔드 빌드가 필요합니다.

**1. 프론트엔드 빌드**

```bash
# frontend 폴더에서 아래 명령어를 실행하여 UI를 빌드합니다.
npm run build
```

**2. 백엔드 서버 실행**

```bash
# backend 폴더에서 아래 명령어를 실행하여 서버를 시작합니다.
python main.py
```

서버가 시작되면 잠시 후 웹 브라우저에 대시보드 화면이 자동으로 열립니다.

**앱 종료**: 앱을 완전히 종료하려면, 반드시 대시보드 우측 상단의 **'Quit Application'** 버튼을 클릭해야 합니다.

## 📖 3. 핵심 기능 및 사용법

대시보드는 총 5개의 주요 기능(위젯)으로 구성되어 있습니다.

#### ① 실시간 위험 감지 (Live Camera Feed)
*   **기능**: 웹캠을 통해 어르신의 활동을 실시간으로 보여주고, AI 영상 분석 기술(OpenCV)을 활용하여 넘어짐과 같은 갑작스러운 큰 움직임을 감지하여 경고합니다.
*   **사용법**:
    1.  앱 실행 시 브라우저의 웹캠 사용 권한 요청에 '허용'을 클릭합니다.
    2.  실시간 영상이 화면에 나타납니다.
    3.  평소에는 상태가 초록색 'OK'로 표시됩니다.
    4.  넘어짐으로 의심되는 큰 움직임이 감지되면, 상태가 빨간색 'POTENTIAL FALL DETECTED'로 즉시 변경되어 위험 상황을 알려줍니다.

#### ② 어르신 프로필 (Senior's Profile)
*   **기능**: 어르신의 이름, 나이, 주요 병력 등 핵심 정보를 한눈에 확인하고 관리합니다. 이 정보는 앱을 껐다 켜도 유지됩니다.
*   **사용법**:
    1.  'Edit Profile' 버튼을 클릭하여 수정 모드로 전환합니다.
    2.  이름, 나이, 병력 등을 수정한 후 'Save' 버튼을 눌러 정보를 저장합니다.

#### ③ 복약 스케줄 (Medication Schedule)
*   **기능**: 매일 복용해야 하는 약의 종류, 복용량, 시간을 목록으로 관리하여 잊지 않도록 돕습니다.
*   **사용법**:
    1.  하단의 입력란에 약 이름, 복용량, 시간을 각각 입력합니다.
    2.  'Add Medication' 버튼을 누르면 목록에 추가됩니다.
    3.  삭제가 필요한 경우, 각 항목 옆의 'X' 버튼을 클릭합니다.

#### ④ 긴급 연락처 (Emergency Contacts)
*   **기능**: 가족, 주치의, 119 등 비상 상황에 필요한 연락처를 목록으로 관리하여 신속하게 대응할 수 있도록 합니다.
*   **사용법**:
    1.  하단의 입력란에 이름, 전화번호, 관계를 입력합니다.
    2.  'Add Contact' 버튼을 눌러 목록에 추가합니다.
    3.  'X' 버튼으로 삭제할 수 있습니다.

#### ⑤ 일일 기록 (Daily Notes)
*   **기능**: 그날의 어르신 건강 상태나 활동 중 특이사항을 간단히 메모하고 시간 순으로 확인할 수 있습니다.
*   **사용법**:
    1.  텍스트 입력란에 내용을 작성합니다.
    2.  'Save Note' 버튼을 누르면, 현재 시간과 함께 기록이 목록 상단에 추가됩니다.

## 🛠️ 4. 기술 스택 및 아키텍처

#### 프론트엔드 (Frontend)
*   **구현 기술**: React, Bootstrap, JavaScript (JS)
*   **구조 및 기능**:
    *   `src/App.js` 파일이 애플리케이션의 메인 진입점 역할을 합니다.
    *   UI는 `src/components` 폴더 안의 작은 컴포넌트들(WebcamFeed, Profile, Medications 등)로 나뉘어 관리되며, `App.js`는 이 컴포넌트들을 조합하여 전체 대시보드 화면을 구성합니다.

#### 백엔드 (Backend)
*   **구현 기술**: Python, FastAPI, Uvicorn, SQLAlchemy, OpenCV, PyInstaller
*   **구조 및 기능**:
    *   `main.py` 파일이 백엔드 서버의 모든 로직을 포함하고 있습니다.
    *   **API 제공**: 프론트엔드에 필요한 데이터(프로필, 약물 정보 등)를 JSON 형태로 제공합니다.
    *   **데이터베이스 관리**: SQLAlchemy를 통해 SQLite 데이터베이스에 정보를 저장, 수정, 삭제합니다.
    *   **웹캠 영상 처리**: WebSocket(` /ws/video`)을 통해 프론트엔드에서 전송된 영상 프레임을 받아 OpenCV로 움직임을 분석하고, 위험 상황을 감지하여 다시 프론트엔드로 전송합니다.

#### 종합적인 작동 원리
1.  **실행**: 백엔드 서버(`main.py`)가 실행되면, 자동으로 웹 브라우저에 프론트엔드 화면을 띄웁니다.
2.  **데이터 연동**: 프론트엔드는 백엔드의 API를 호출하여 데이터를 가져와 화면에 표시합니다.
3.  **영상 스트리밍 및 분석**: 웹캠 영상이 실시간으로 백엔드에 전송되어 움직임을 분석하고, 이상 상황 감지 시 그 결과가 다시 프론트엔드 화면에 경고로 표시됩니다.

## 💡 5. 추가 기능 제안 및 보안 개선점

#### 추가 가능한 기능
*   **정교한 낙상 감지**: 자세 추정(Pose Estimation) AI 모델을 도입하여 정확도 향상.
*   **복약 관리 및 알림**: 지정된 시간에 알림을 보내고 복용 여부를 기록.
*   **자동 긴급 연락 시스템**: 위험 감지 시 등록된 연락처로 SMS/전화 자동 발송 (e.g., Twilio API 연동).
*   **원격 접속 및 다중 사용자 지원**: 클라우드 배포 및 사용자 계정 시스템 도입.
*   **양방향 소통 채널**: WebRTC를 활용한 영상/음성 통화 기능 추가.
*   **건강 데이터 시각화**: 기록된 데이터를 차트/그래프로 시각화.

#### 해결해야 할 보안점
*   **인증 및 인가 부재**: 현재 로그인 기능이 없어 모든 정보가 노출됨. -> **JWT 기반 로그인 시스템 도입 필요**.
*   **안전하지 않은 서버 종료 기능**: 인증 없이 서버 종료 API 호출 가능. -> **관리자 권한 검증 필요**.
*   **암호화되지 않은 통신**: HTTP/WS 사용으로 중간자 공격에 취약. -> **HTTPS/WSS 적용 필요**.
*   **입력값 검증**: 악의적 입력값에 대한 방어 로직 강화 필요.
